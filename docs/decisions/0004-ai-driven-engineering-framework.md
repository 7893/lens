# ADR-0004: 全面确立 AI 驱动与人机协同研发范式总纲

更新日期：2026-09-19
状态：采纳
责任人：@lens-team
适用范围：Lens 全仓软件工程生命周期、多 Agent 协作体系与代码治理规范

---

## 背景 (Context)

传统的软件工程体系完全建立在“纯人类工程师阅读、编写与心智维护”的前提之下。在现代生成式 AI 与编码 Agent 深度参与日常开发的过程中，传统模式暴露出四大结构性痛点：

1. **上下文过载与盲人摸象**：面对庞大的 Monorepo 代码库，通用大模型常依赖粗暴的全文检索（`grep` / `find`），消耗巨额 Token 窗口，却极易丢失动态调用关系与跨文件因果依赖；
2. **缺乏边界导致越界修改**：缺乏严格的领域划分与权限约束时，AI 往往在处理单点需求时盲目扩散修改范围，引发意料之外的退化（Regression）；
3. **真相分裂与文档掉队**：需求与实现快速演化，而文档与决策记录未能强同步，导致后续 Agent 基于过时或编造的信息进行开发，产生严重的逻辑幻觉；
4. **过度依赖“自觉防线”**：将规则写在自然语言提示词中只能作为“须知”，无法在动作发生点提供确定性的硬性拦截。

Lens 作为运行在 Cloudflare 边缘计算栈之上的高性能、低延迟应用，必须在工程底层实现范式革新，使代码库具备 **AI-Native（AI 友好且具备严密确定性护栏）** 的本质特征。

---

## 决策 (Decision)

我们决定正式确立 Lens 项目全面转向 **AI 驱动与人机协同研发范式（AI-Native Collaborative Engineering Paradigm）**，并将以下**四大工程支柱**确立为项目长期演进的技术宪章：

### 1. 双层认知导航图谱体系 (Navigation)

- **微观 AST 符号网络（CodeGraph）**：在本地维护符号、定义、调用链与动态分发拓扑。AI 进行代码定位时，必须优先使用 `codegraph explore` 瞬时直达调用链路，严禁盲目扫描；
- **宏观架构知识全景（Graphify）**：在本地维护全仓模块、社区划分与依赖因果图。AI 在评估架构方案或评估修改影响面时，必须优先通过 `graphify query` / `path` 测算爆炸半径（Blast Radius）；
- **衍生资产隔离**：所有本地 AI 索引与缓存数据（`.codegraph/`, `graphify-out/`）由 Git 严格忽略，保持版本库纯粹轻盈。

### 2. 领域边界与上下文收敛 (Domain Scoping via Local Harness)

- 依托统一的 Harness 体系（`.pi/harness.json`），将项目划分为明确的 6 大领域：`engine`（边缘后端）、`client`（前端交互）、`shared`（共享契约与类型）、`docs`（项目文档）、`tooling`（工程工具链）、`infra`（云基础设施）；
- AI 接入任务前必须通过 Harness 限定领域，只读取受限领域索引；提交前由 Harness 规划并执行对应领域的针对性验收检查，阻断范围漂移。

### 3. 契约化约束与单一事实源 (Single Source of Truth & Contracts)

- **活死分离原则**：
  - **活文档（Living）**：以 `docs/CURRENT-STATE.md` 为系统当前事实最高入口，随代码改动必须原子同步；
  - **死文档（Frozen）**：重大技术抉择必须沉淀为 ADR（`docs/decisions/`），写完即冻结，正文只增不改，改动时以新增记录标记取代（Supersede）；
- **仓内全景闭环**：通过 `docs/INDEX.md` 索引全量存活文档，通过 `docs/KNOWN-ISSUES.md` 跟踪技术债务，彻底消除外部 Issue 系统与代码的割裂。

### 4. 动作点自动化机器闸门 (Automated Enforcement Gates)

- **不依赖自觉**：红线不仅写在规范中，更必须作为刚性闸门部署在动作发生点；
- 通过 `scripts/check_docs.mjs`、`pnpm test`、`typecheck`、`lint` 和部署 dry-run 形成多层拦截网，在 Git 提交与 CI 流水线中机械阻断坏链、死代码、格式偏差与安全漏洞。

### 5. 人机协作权责模型 (Human-AI Division of Responsibility)

- **项目负责人（人类/Owner）**：拥有最终决策权、高危操作授权权（如远端 D1 变更、生产发布密钥）与架构方案审阅权；
- **AI Coding Agent**：承担需求剖析、图谱溯源、方案推演、高质量代码编写、单测补充、文档同步与全量回归验证的闭环实施职责。

---

## 理由与考量 (Rationale)

- **质的效率提升**：相较于仅将 AI 当作代码补全工具的初级用法，图谱导航使 AI 上下文读取精准度提升数倍，单任务上下文消耗大幅下降；
- **极佳的工程鲁棒性**：Harness 领域隔离与动作点机器闸门构建了安全防护网，使得即便由多款不同 AI Agent 或人类轮流维护，代码风格与架构规范依然高度一致；
- **消除技术债务复利**：死代码清理、安全漏洞扫描与文档治理被固化为自动化命令，防止无用依赖和过期逻辑隐蔽滋生。

---

## 影响与后果 (Consequences)

- **正面收益**：Lens 代码库正式具备了自解释、自验证与可进化能力，研发流转敏捷度与生产安全性达到工业级标准；
- **工程纪律要求**：
  - 核心逻辑调整后，开发者与 AI 必须执行 `codegraph sync` 或 `graphify update .` 保持认知图谱新鲜；
  - 必须严格执行已签名提交规范（Signed Commit）并通过所有领域门禁。
