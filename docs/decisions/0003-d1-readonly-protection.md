# ADR-0003: 生产 D1 数据库只读保护与安全防线

更新日期：2026-09-18
状态：采纳
责任人：@lens-team
适用范围：D1 数据库连接、开发环境工具、数据库迁移与 AI 行为红线

---

## 背景 (Context)

Lens 项目依赖 Cloudflare D1 存储海量图片元数据、FTS5 全文索引和 AI 质量评分。
在自动化 AI 辅助编码或本地调试过程中：

1. 存在误执行批量删除（`DELETE FROM images`）、清表（`TRUNCATE` / `DROP TABLE`）或覆盖式迁移的极端风险；
2. 一旦线上数据库损坏，需要耗费大量时间重新从 Unsplash 和 AI 重新生成索引，代价极高。

## 决策 (Decision)

我们确立了**生产 D1 数据库绝对只读防线**：

1. **AI 行为硬约束**：AI 严禁对远程 D1 数据库执行任何形式的写操作、结构变更（DDL）或批量删除；
2. **Schema 变更受控**：所有数据库结构变动必须通过 `apps/engine/migrations/` 下的版本化 SQL 迁移脚本管理，由人类工程师审阅后通过受控流程应用；
3. **本地开发无害化**：本地单元测试全部基于内存 Mock 或隔离的测试上下文运行，杜绝连接线上生产库进行破坏性验证。

## 理由与考量 (Rationale)

- **防范灾难性误操作**：通过制度与契约筑牢第一道防线，避免“一个错误命令摧毁生产库”；
- **版本化追溯**：D1 表结构有据可查，每一次变更与迁移脚本严格对应。

## 影响与后果 (Consequences)

- **正面收益**：线上数据安全性得到根本性保障；
- **权衡**：涉及数据库字段新增时，必须按规范编写迁移脚本并经过审查，稍增操作步骤，但保障了生产稳定性。
