# Lens 系统架构与边缘检索设计规约

更新日期：2026-09-19
状态：现行
适用范围：Lens 宏观系统拓扑、边缘混合检索流、异步采集流水线与状态机编排

Lens 是部署于 Cloudflare 边缘运行时的多模态混合检索系统。系统针对 Serverless 边缘环境（内存限制 128MB、执行时间片受限、外部 API 配额有限）进行工程约束设计，通过单 Worker 进程模型内聚 API 服务、队列消费者、定时调度器与分布式持久化工作流。

---

## 1. 宏观架构：单 Worker 全栈内聚模型

Lens 采用 **“统一计算进程，按触发器逻辑解耦”** 的单 Worker 架构模式。所有运行入口均收敛在 `@lens/engine` 中，避免多 Worker 微服务之间的 RPC 延迟与子请求计数损耗：

```text
                                 [客户端请求 / Cron / Queue]
                                             │
                                             ▼
                             ┌──────────────────────────────┐
                             │       @lens/engine 入口       │
                             └──────────────┬───────────────┘
                                            │
                    ┌───────────────────────┼──────────────────────┐
                    ▼                       ▼                      ▼
           [HTTP / API 路由]         [Cron 定时触发器]      [Queue 队列消费者]
                    │                       │                      │
           ┌────────┴────────┐      ┌───────┴────────┐     ┌───────┴────────┐
           │ Hono 路由网关   │      │ Ingestion /    │     │ 批量任务解包   │
           │ 参数校验与追踪  │      │ Evolution 调度 │     │ 触发 Workflows │
           └────────┬────────┘      └───────┬────────┘     └───────┬────────┘
                    │                       │                      │
                    ▼                       ▼                      ▼
           [混合检索服务]           [边界探测与任务派发]   [持久化状态机执行]
           (SearchService)          (Queue Producer)       (WorkflowProcessor)
```

### 1.1 同步搜索管道 (Synchronous Hybrid Search Pipeline)

搜索管道结合了 **“倒排索引 (FTS5) + 语义稠密向量 (Vectorize)”** 的混合检索链路：

1. **L1 HTTP 边缘缓存**：利用 Cloudflare 边缘 `caches.default` 缓存高频完全相同的搜索请求响应；
2. **L2 语义缓存层 (KV)**：将标准化查询词及其扩展向量映射缓存，减少重复的推理计算；
3. **双路并发召回**：
   - **关键词路 (D1 FTS5)**：基于 SQLite 全文搜索模块执行分词匹配，保证专业术语、人名与标签的精准命中；
   - **语义稠密向量路 (Vectorize)**：基于 BGE-M3 提取的 768 维稠密向量执行 TopK 余弦相似度召回；
4. **倒数排名融合 (RRF)**：将两路召回结果按位置排序加权融合，计算综合相关性得分；
5. **断崖截断过滤 (Cliff Detection)**：遍历综合得分序列，检测相邻候选结果的得分变化率阶跃，动态截断低相关性长尾。

### 1.2 异步采集与演进管道 (Asynchronous Pipeline)

由队列与状态机驱动的异步摄取架构：

- **增量发现与对撞 (IngestionService)**：定时检查外部图源并执行边界检测；
- **任务分发缓冲 (Cloudflare Queue)**：解耦抓取发现与深度计算，吸收并发尖峰；
- **分布式状态机 (Workflows)**：通过 `WorkflowProcessor` 保证图片下载、AI 视觉推理、向量入库与元数据落库具备步骤级持久化与故障自愈能力。

## 2. 增量发现与线性边界对撞模型 (Linear Boundary Collision)

由于外部数据源（如 Unsplash API）具有严格的速率限制（50 次请求/小时），系统设计了 **“边界对撞探测算法”** 以最小化 API 请求消耗。

### 2.1 算法逻辑

1. **广告与赞助内容过滤**：在反序列化阶段直接丢弃 `sponsorship !== null` 记录，消除非时间轴连续的干扰数据；
2. **正向对撞探测**：采集器从最新一页（Page 1）按时间轴倒序向历史拉取。一旦当前批次中的图片 ID 已存在于 D1 数据库中，判定为“触碰已知边界”并立即熔断翻页，退出当前周期；
3. **事务化锚点推进**：只有在当前批次所有新图片确认成功写入 Queue / Workflows 后，才在 D1 的 `system_config` 表中推进 `last_seen_id`。这一顺序避免了并发或中断导致的数据遗漏。

## 3. 分布式追踪与可观测性体系 (Distributed Tracing)

系统全面遵循 W3C Trace Context 规范，支持跨组件全链路调用链染色：

### 3.1 追踪指纹分类

进入系统的每个独立业务流均被分配唯一追踪标识：

- `SEARCH-xxxx`：追踪单个用户搜索请求的各阶段耗时（FTS5 检索、向量召回、RRF 融合、序列化）；
- `CRON-xxxx`：追踪每小时定时调度执行时的 API 配额与发现数量；
- `WF-photoId-xxxx`：追踪单张图片在多阶段状态机中的每个 Step 状态及重试次数。

### 3.2 上下文传播与排错

- 在 HTTP 入口处自动提取或生成标准 `traceparent` 请求头；
- 在 API 响应中回显 `x-trace-id`；
- 日志系统（`Logger`）自动附加该上下文指纹，开发者可通过 `GET /api/trace/:id` 直接回溯特定链路的完整生命周期。

## 4. 异步批处理并发架构 (Queue + Workflow Concurrency)

针对存量图片重刷与批量采集需求，系统采用生产者-消费者异步解耦架构：

### 4.1 并发配置矩阵 (wrangler.toml)

| 调度参数            | 配置值 | 含义                                            |
| :------------------ | :----- | :---------------------------------------------- |
| `max_batch_size`    | 5      | 每个 Queue Consumer 实例每批次最多拉取 5 条消息 |
| `max_batch_timeout` | 30s    | 批次等待聚合超时时间                            |
| `max_concurrency`   | 5      | 最大并发运行的 Queue Consumer 实例数            |

### 4.2 运行性能与指标

- **理论并发峰值**：5 个 Consumer 实例 × 5 消息批次 = 25 个并发 Workflows 实例；
- **单图处理延迟**：约 2.5 ~ 3.5 秒（涵盖 R2 流式拉取、多模态视觉属性推理、BGE-M3 向量化、D1 + Vectorize 写入）；
- **实测批处理吞吐量**：约 450 ~ 500 张/分钟；
- **故障隔离与可恢复性**：每个 Workflow 步骤状态（Download, Vision, Embedding, Persist）持久化于 Workers 状态存储，个别失败仅重试单一阶段，杜绝全流程返工。

## 5. 存储架构与多模态模型协作

系统在推理链路上坚持模块职责隔离，避免单点过载：

| 业务处理阶段     | 使用模型 / 组件       | 技术职责                                         |
| :--------------- | :-------------------- | :----------------------------------------------- |
| **视觉属性理解** | Llama 视觉多模态模型  | 提取图片构图标签、语义摘要描述与结构化命名实体   |
| **查询意图扩展** | Llama 3.2 3B Instruct | 针对口语化或跨语言查询生成标准视觉检索联想词     |
| **向量化基座**   | BGE-M3 (768 维)       | 生成跨模态文本特征稠密向量，映射至多语言语义空间 |
| **关键词倒排**   | SQLite FTS5           | 处理确定性关键词、作者名称与高频标签匹配         |
| **关系持久化**   | Cloudflare D1         | 存储经过类型校验的标准图片元数据与系统配置       |
| **向量持久化**   | Cloudflare Vectorize  | 存储稠密向量索引并支撑 TopK 近似近邻（ANN）查询  |
| **介质持久化**   | Cloudflare R2         | 统一存储优化后的图片展示二进制流（WebP）         |

## 6. 边缘运行时边界与工程硬约束

1. **内存边界**：单个请求/执行上下文的内存上限严格受限于 128MB。图片下载与上传强制采用 `ReadableStream` 流式管道传输，严禁将大文件一次性缓冲到内存；
2. **CPU 时间片**：单次 HTTP 请求的实际 CPU 执行时间应保持在 50ms 以内（IO 等待不计入 CPU 时间），高耗时计算必须下沉到 Workflows；
3. **数据库只读防护**：线上生产 D1 数据库严禁任何无版本化迁移脚本支撑的结构变动与批量清表操作。
